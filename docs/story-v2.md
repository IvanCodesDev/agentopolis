# Proof of Quest：自由设计师的隐形项目

版本：Demo Story V0.2  
目标网络：Monad Testnet  
表现形式：单一、连续、可交互的像素动漫世界  
故事时长：完整体验约 8–12 分钟；黑客松舞台演示 3–5 分钟

## 1. 文档目标

这不是把任务后台换成像素皮肤，而是让玩家亲历一名自由设计师在现实外包链条中的完整处境：

> 甲方把项目交给工作室，工作室承担客户沟通与交付责任，自由设计师完成具体设计；项目结束后，客户资料和源文件仍保持私密，但工作室在 Monad 上确认设计师的真实贡献。后来，HR 不需要登录或连接钱包，就能核验这段经历由谁签发、声明了什么、现在是否有效。

Demo 必须同时讲清四件事：

1. 工作室不是反派。它负责获客、需求翻译、报价、收款、返工和客户责任。
2. 自由设计师真正完成了工作，但传统证据散落在群聊、转账和私密文件中。
3. Monad 证明的是“某个工作室钱包作出了这项声明，且声明未被改写、当前未被撤销”，不是自动证明审美、版权或陈述绝对真实。
4. 客户名称、联系方式、报价、利润、聊天记录和源文件不进入链上公开记录。

## 2. 现实案例底稿

### 2.1 项目

- 内部项目：某国产护肤品牌夏季新品电商详情页。
- 对外匿名类别：电商视觉设计。
- 设计任务：1 张主视觉、6 屏商品详情页、移动端适配，两轮修改。
- 直接上游：光谷设计工作室。
- 实际执行者：自由设计师小墨。
- 甲方联系人：陈经理，仅与工作室沟通，不直接成为链上签发者。
- 时间：7 月 3 日接单，7 月 20 日验收。
- 公开角色：详情页执行设计师。
- 公开摘要：完成 6 屏商品详情页视觉排版、移动端适配与两轮修改。
- 证据等级：工作室确认 + 验收版本文件指纹。

### 2.2 V1 与 V2

V1 不是为了制造戏剧冲突，而是呈现真实项目中的需求翻译和返工：

- 小墨在 7 月 12 日提交 V1；
- 陈经理认为首屏产品卖点不够突出、成分图标太偏科技感、移动端字号偏小；
- 岚姐把甲方的模糊意见整理成三个可执行修改项；
- 小墨提交 V2，调整信息层级、替换图标语言、完成移动端适配；
- 陈经理确认“V2 可以上线”；
- 岚姐作为直接派单并验收的人，确认小墨的贡献。

### 2.3 为什么甲方不直接上链

甲方仍只面对工作室。客户真实身份、联系方式、合同、预算和内部反馈均留在原有商业关系中。Monad 凭证记录的是工作室对下游贡献的声明，而不是把甲方拉进新的平台流程。

## 3. 角色

### 小墨：自由设计师 / 玩家

- 做过很多真实外包，却常因统一署名和保密要求无法证明经历。
- 需要的不是公开客户文件，而是一条可以随自己离开群聊和平台的协作确认。

### 岚姐：光谷设计工作室负责人 / 签发方

- 从甲方获得订单，负责报价、需求翻译、进度、质量、收款和售后。
- 希望给可靠设计师留下记录，但不能暴露客户资源和利润结构。
- 用工作室钱包签发和撤销 Monad 凭证。

### 陈经理：甲方客户 / 链下角色

- 只要求一个责任主体，关注上线时间和转化表达。
- 反馈通过工作室传递，不连接钱包，也不公开身份上链。

### 林然：品牌公司 HR / 验证方

- 收到小墨的简历和作品集，但无法仅凭截图判断真实项目、具体角色和验收状态。
- 无需登录、无需钱包，通过访客终端读取 Monad 上的核心记录。

### 墨点：引导精灵

- 用普通语言解释文件指纹、链上声明和信任边界。
- 不说“区块链保证一切真实”。

## 4. 世界结构

```text
设计师小屋
  │ 作品墙 / 旧群聊 / 求职邮件
  ▼
雨夜街道 ── 甲方通讯塔（只能看见工作室与甲方通信）
  ▼
光谷委托公会
  │ 匿名任务板 / 岚姐 / 私密档案柜
  ▼
像素设计工坊
  │ V1 工作台 / 反馈信箱 / V2 工作台 / 文件指纹机
  ▼
公会验收厅
  │ 验收卷轴 / 隐私过滤镜 / Monad 契约台
  ▼
职业记忆广场
  │ 冒险者护照 / 贡献记忆碑 / HR 访客终端
  ▼
异常档案室
     撤销演示 / 历史保留
```

这是一个连续世界。角色移动承担主导航；表单只作为与物件互动时出现的轻量浮层。

## 5. 完整剧情与逐场景交互

### 场景 0：序章——简历上的空白

**地点**：设计师小屋  
**剧情状态**：`INTRO`  
**交互物**：作品墙、旧群聊终端、求职邮件

作品墙显示精美项目，但角落统一盖着“不可公开客户信息”。

小墨：

旧群聊终端：

> “详情页今晚能改完吗？”  
> “收到，第二版已上传。”  
> “尾款已转。”

小墨：

> 聊天里有任务、修改和转账，但也有客户名字、价格和联系方式。我不能把整段截图发给招聘方。

求职邮件弹出：

> 林然 HR：作品不错。请问这个商业项目是否真实？你负责的是主设计还是执行？有没有上游验收证明？

小墨：

> 我有作品，却没有一份别人能低成本核验的项目关系证明。

墨点：

> 今天公会有一份新的匿名委托。它不会公开客户，却可以在完成后留下协作方确认。

**界面信息**

- 当前困境：有作品 / 缺少可验证经历
- 主任务：前往光谷委托公会

### 场景 1：甲方把需求交给工作室

**地点**：甲方通讯塔外侧  
**剧情状态**：`CLIENT_BRIEF_RECEIVED`  
**表现**：玩家旁观岚姐与陈经理的通讯，不直接接触客户资料

陈经理：

> 我们七月底要上新。需要一张主视觉和 6 屏详情页，移动端也要看清卖点。我们只对接你们工作室，时间和质量由你们负责。

岚姐：

> 明白。我会拆解需求、安排执行、统一收稿。您仍然只需要和我确认版本。

墨点：

> 中间承接者承担了真实责任。Proof of Quest 不让设计师绕过工作室，而是在交付之后补上贡献记录。

**不向玩家公开**

- 客户真实名称
- 联系方式
- 合同金额和工作室报价
- 利润与支付记录

### 场景 2：公会创建匿名委托

**地点**：光谷委托公会  
**剧情状态**：`QUEST_AVAILABLE`  
**交互物**：任务板、岚姐、私密档案柜

任务板：

> 匿名委托 #PQ-2407-0168  
> 类别：电商视觉设计  
> 角色：详情页执行设计师  
> 交付：1 张主视觉、6 屏详情页、移动端适配  
> 预计修改：2 轮  
> 保密等级：匿名行业  
> 预计完成：7 月 20 日

岚姐：

> 这份工作来自现有客户。客户关系、合同和报价仍由工作室保管。你只会看到完成任务需要的信息。

小墨：

> 如果我完成了，证明里会公开客户吗？

岚姐：

> 不会。公开记录只写项目类别、你的角色、匿名摘要、文件指纹和我的确认。客户资料不进入 Monad。

玩家选择：

- `接受匿名委托`
- `查看公开字段`
- `查看不会公开的字段`

接受确认：

> 你正在以钱包 `0xDesigner…` 接受任务。最终凭证只能签发给这个地址。

### 场景 3：设计与 V1 提交

**地点**：像素设计工坊  
**剧情状态**：`QUEST_ACCEPTED → V1_SUBMITTED`  
**交互物**：素材箱、排版桌、预览屏、V1 提交箱

通过三次轻交互表现真实工作，不做复杂设计模拟器：

1. 把“核心卖点”卡片拖到首屏主层级；
2. 为 6 屏页面选择统一网格；
3. 切换移动端预览，检查字号和间距。

小墨：

> 我不是在平台里凭空点一下“完成”。真实设计仍在原来的工具中完成，这里只记录提交、验收和证据。

V1 提交箱显示：

- 文件：`detail-page-v1.pdf`
- 版本：V1
- 提交时间：7 月 12 日 18:40
- 文件状态：私密
- 操作：计算 SHA-256 指纹

墨点：

> 文件指纹像一枚只对应当前字节内容的印记。它不能证明版权，却能帮助核对“后来拿出的文件是否就是当时验收的版本”。

提交结果：

> V1 已发送给工作室。原文件不公开，尚未上链。

### 场景 4：甲方反馈被翻译成可执行修改

**地点**：反馈邮局  
**剧情状态**：`V1_REVIEWED → REVISION_REQUESTED`  
**交互物**：甲方原始留言、岚姐的修改清单

甲方原始留言：

> 第一屏感觉还不够抓人，图标有点硬，手机上字也有点小。整体再柔和一点。

岚姐：

> 客户的反馈很真实，但不够直接。我把它整理成三项：

1. 首屏放大核心卖点，弱化次要参数；
2. 成分图标从科技线框改为柔和的自然形态；
3. 移动端正文最小字号提高，并重新检查 6 屏间距。

岚姐：

> V1 还没有验收，所以不会生成凭证。修改记录保留在链下，避免把客户意见永久公开。

小墨：

> 明白。我按这三项完成 V2。

**界面信息**

- 状态：需要修改
- 版本：V1
- 驳回原因：仅任务双方可见
- 链上动作：无

**地点**：像素设计工坊

**交互物**：V2 工作台、隐私过滤镜、文件指纹机

玩家依次完成三项修改，预览屏从 V1 切换到 V2。

V2 提交信息：

- 版本：V2
- 文件大小：演示文件实际值

> 为【客户真实品牌名】完成 ¥XXXX 项目，负责 6 屏详情页和微信沟通。

> 完成 6 屏商品详情页视觉排版、移动端适配与两轮修改。

小墨：

> 这句话足以说明我的贡献，又不会暴露客户是谁、工作室赚多少或源文件内容。

岚姐：

墨点：

> 甲方完成了原有商业验收，却不需要注册新平台或连接钱包。接下来，由直接派单、查看过程并承担交付责任的工作室确认小墨的贡献。

### 场景 7：公会验收与上链预览

**地点**：公会验收厅  
**剧情状态**：`CLIENT_ACCEPTED → APPROVED`  
**交互物**：版本档案、验收卷轴、公开/私密分界台

岚姐查看：

- V1 提交时间及私密文件信息；
- V1 修改原因；
- V2 验收版本和 SHA-256；
- 去标识公开摘要；
- 被邀请设计师钱包。

岚姐：

> 我确认，小墨确实以“详情页执行设计师”的角色完成了 V2 和两轮修改。客户信息继续留在工作室档案里。

公开/私密分界台：

| 将写入 Monad | 只保存在链下私密空间 |
|---|---|
| 工作室钱包 | 客户真实名称 |
| 设计师钱包 | 联系方式 |
| 匿名项目引用 `projectRefHash` | 内部 `projectId` 与随机盐 |
| 文件指纹 `evidenceHash` | PDF/源文件本体 |
| 电商视觉设计 | 合同、报价与利润 |
| 详情页执行设计师 | 原始聊天和完整需求 |
| 去标识公开摘要 | V1 驳回细节 |
| 签发时间与撤销状态 | 甲方内部意见 |

确认勾选：

> 我确认该设计师完成了上述贡献；我理解公开字段将写入 Monad，错误记录只能撤销，不能抹去历史。

### 场景 8：Monad 签发

**地点**：Monad 契约台  
**剧情状态**：`APPROVED → ATTESTING → CREDENTIAL_ISSUED`  
**签发方**：岚姐的工作室钱包

钱包弹层：

> 将由 `0xIssuer…` 为 `0xDesigner…` 签发不可转让的贡献凭证。  
> 这不是 NFT，不涉及支付，也不会转移客户资料。

交易状态映射：

- 等待钱包：契约台出现待盖印卷轴；
- 用户拒签：卷轴收回，任务保持已验收，可重试；
- 交易发送：紫色 Monad 光流进入城镇；
- 交易成功：贡献记忆碑点亮；
- RPC 失败：显示“暂时无法链上核验”，绝不伪装成功；
- 网络错误：提示切换到 Monad Testnet。

成功信息：

- Credential ID：运行时真实值
- Transaction Hash：运行时真实值
- Issuer：工作室钱包
- Designer：小墨钱包
- Status：有效

岚姐：

> 我签下的不是对你审美高低的判决，而是我对这段协作事实负责。

小墨：

> 客户资料仍然保密，但这次贡献终于不只留在群聊里。

### 场景 11：撤销不是删除

**地点**：异常档案室  
**剧情状态**：`CREDENTIAL_ISSUED → CREDENTIAL_REVOKED`  
**演示方式**：用预置的第二条凭证，避免破坏主故事的有效凭证

预置案例：

> 工作室签发后发现接收地址填错，必须撤销旧凭证并重新签发。

只有原签发方钱包可以操作：

> 撤销原因：接收钱包地址填写错误。  
> 注意：撤销后历史仍保留，但凭证不应继续作为有效证明。

撤销动画：

- 石碑不会消失；
- 紫色光芒熄灭；
- 出现红色封印“REVOKED / 已撤销”；
- 原始签发内容和撤销时间仍可查看。

林然刷新访客终端：

> 状态：已撤销。该记录不应作为有效职业证明使用。

墨点：

> 可撤销解决错误和失效问题；保留历史防止签发方悄悄改写过去。

## 6. 状态机

```text
INTRO
→ CLIENT_BRIEF_RECEIVED
→ QUEST_AVAILABLE
→ QUEST_ACCEPTED
→ V1_SUBMITTED
→ REVISION_REQUESTED
→ V2_SUBMITTED
→ CLIENT_ACCEPTED
→ APPROVED
→ ATTESTING
→ CREDENTIAL_ISSUED
→ SHARED
→ VERIFIED

V1_SUBMITTED → REVISION_REQUESTED → V2_SUBMITTED
APPROVED → ATTESTING_FAILED → APPROVED
CREDENTIAL_ISSUED → CREDENTIAL_REVOKED
```

链上交易未成功时，场景不能进入 `CREDENTIAL_ISSUED`。撤销后保留原凭证内容。

## 7. PRD 字段到像素物件映射

| PRD / 合约字段或状态 | 像素物件 | 玩家看到的意义 |
|---|---|---|
| `issuer` | 公会印章、岚姐钱包徽记 | 谁对贡献声明负责 |
| `designer` | 冒险者护照地址栏 | 凭证签给谁 |
| `projectRefHash` | 匿名委托编号水晶 | 可引用同一项目，但无法直接猜客户 |
| `evidenceHash` | 文件指纹机生成的符文 | 核对验收文件字节是否一致 |
| `projectCategory` | 任务板职业类别徽章 | 电商视觉设计 |
| `role` | 护照职业铭牌 | 详情页执行设计师 |
| `publicSummary` | 验收卷轴公开段落 | 可展示的具体贡献 |
| `issuedAt` | 记忆碑刻印时间 | 何时签发 |
| `revokedAt` | 红色撤销封印与时间 | 是否及何时失效 |
| `DRAFT / INVITED` | 未亮起 / 发光任务板 | 任务已创建和邀请 |
| `ACCEPTED` | 玩家背包中的委托卷轴 | 设计师确认参与 |
| `SUBMITTED` | 公会信箱里的文件封套 | 成果等待验收 |
| `REJECTED` | V1 上的修改便签 | 未验收，不签发 |
| `APPROVED` | 已盖链下验收章的卷轴 | 贡献已确认，待上链 |
| `ATTESTING` | 流向 Monad 的紫色光流 | 交易处理中 |
| `ISSUED` | 点亮的职业记忆碑 | 链上凭证有效 |
| `REVOKED` | 不消失的破损石碑和红封印 | 历史保留，凭证失效 |
| 隐私级别 | 隐私过滤镜 / 档案柜 | 控制公开摘要，不公开原资料 |
| 私密对象存储 | 上锁的公会档案柜 | 文件存在但访客不能下载 |
| 公开验证链接 | 分享水晶 / 访客通行证 | HR 无钱包进入核验 |
| RPC 读取失败 | 失去信号的访客终端 | 无法验证，而非默认有效 |

## 9. 3–5 分钟舞台演示脚本

### 0:00–0:30 现实困境

移动小墨检查作品墙、旧群聊和 HR 邮件。

讲解：

> 小墨做过真实商业设计，但客户只认识工作室。她不能把包含品牌、价格和联系方式的群聊截图交给 HR，因此作品能展示能力，却难以证明项目关系。

### 0:30–1:05 上游与匿名委托

经过甲方通讯塔，看见陈经理把任务交给岚姐；进入公会接受匿名电商详情页任务。

讲解：

> 我们不消灭工作室。工作室继续负责客户、报价、沟通与售后。平台只把任务匿名派给设计师，并约定验收后留下贡献确认。

### 1:05–1:50 V1 反馈与 V2

展示 V1 提交、甲方模糊反馈、岚姐整理三项修改、小墨完成 V2。用预置文件实时计算 SHA-256。

讲解：

> 这里记录了真实的修改过程。V1 未通过就不会签发。V2 文件保持私密，只把验收版本指纹用于日后核对。

### 1:50–2:25 隐私边界

在隐私过滤镜中把包含客户名与价格的摘要改成去标识版本；打开公开/私密分界台。

讲解：

> 客户名称、价格、合同、聊天和设计文件都不上链。Monad 只记录工作室和设计师地址、匿名项目引用、角色、摘要、文件指纹和状态。

### 2:25–3:15 Monad 签发

切换到岚姐钱包，确认验收并调用真实合约。展示钱包确认、交易中和石碑点亮。

讲解：

> 工作室为自己看到和验收的事实负责。交易成功后才点亮记忆碑；如果拒签或网络失败，游戏不会假装成功。

### 3:15–4:10 求职与 HR 核验

把凭证加入小墨的简历，切换无钱包访客林然，在访客终端读取 Monad。

讲解：

> HR 不需要钱包，也不用看懂区块浏览器。她能看到谁签发、签给谁、声明了什么、记录是否仍然有效。链上证明声明和状态，不替 HR 判断审美和版权。

### 4:10–4:40 撤销

打开预置的错误地址凭证，由原签发方撤销；刷新访客终端。

讲解：

> 错误凭证可以撤销，但不会从历史中消失。只有原签发方能撤销，HR 会立即看到它已失效。

### 4:40–5:00 结尾

镜头回到小墨的小屋，作品墙旁新增发光的职业记忆。

结尾：

> Proof of Quest 没有把商业资料公开，也没有改变原来的接单关系。它只补上了过去缺失的一次结算：工资结算当次劳动，Monad 凭证结算可携带的职业信用。

## 10. Demo 必须使用真实状态的部分

- V2 示例文件在浏览器中真实计算 SHA-256；
- Monad 签发调用真实部署合约；
- 凭证 ID、交易哈希、签发方、设计师和撤销状态来自链上；
- HR 访客终端无需钱包，直接读取合约；
- 撤销调用真实合约，刷新后状态改变；
- 钱包拒签、错误网络和 RPC 失败有诚实的失败状态。

以下内容可以是固定剧情数据：

- 匿名需求文字；
- V1 与 V2 的视觉缩略图；
- 甲方反馈；
- 工作室链下身份标签；
- 项目日期和演示对白。

## 11. 信任边界固定文案

验证终端首屏必须显示：

> 此记录证明所示工作室钱包曾向所示设计师钱包签发该贡献声明，并显示声明当前是否有效。它不代表平台或 Monad 已独立验证项目真实性、设计水平、版权归属或合同权利。

隐私预览必须显示：

> 链上公开内容无法删除，只能撤销。请勿填写客户名称、联系方式、报价、合同、聊天内容或未发布设计资料。

撤销前必须显示：

> 撤销会将凭证标记为失效，但原始内容和撤销历史仍会保留。

## 12. 项目边界

Demo 不做：

- 自动抓取闲鱼订单或微信群聊天；
- 甲方强制注册、连接钱包或直接签发；
- 支付、托管、分账和发票；
- NFT、Token 或凭证交易；
- 设计能力评分和自动招聘结论；
- 公开作品社区；
- 完整企业 KYC、仲裁和版权判定；
- Base Sepolia、EAS 或多链兼容。

Demo 只证明一个最小事实：

> 光谷设计工作室的钱包在 Monad 上确认：小墨的钱包曾以详情页执行设计师的角色，完成一项匿名电商视觉项目及两轮修改；该声明引用验收文件指纹，并可被公开核验或由原签发方撤销。
