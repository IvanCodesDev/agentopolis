# Proof of Quest 前端页面开发规划

> 产品形态：基于 Monad 的像素职业冒险世界  
> 核心用户：自由设计师、签发公会、HR 验证方  
> 设计目标：有明显的像素风游戏氛围，但核心工作流仍像成熟 Web 产品一样清晰、快速、可信。

## 1. 前端体验原则

### 1.1 游戏感服务于业务状态

像素世界不是装饰性首页，而是业务流程的可视化载体：

| 业务概念 | 游戏化表达 |
| --- | --- |
| 匿名外包任务 | 公会任务卷轴 |
| 设计师 | 冒险者角色 |
| 工作室/项目负责人 | 公会 |
| 文件哈希 | 成果数字指纹 / 魔法印记 |
| 验收 | 公会鉴定 |
| Monad 交易 | 链上铭刻 |
| 职业贡献凭证 | 冒险履历徽记 |
| 撤销 | 凭证失效封印 |

游戏化文案旁必须保留准确的 Web3 术语。例如按钮可以写“铭刻到 Monad”，辅助说明必须明确“这会发起一笔 Monad Testnet 交易”。

### 1.2 交互采用双层结构

- 场景层：像素地图、角色、公告板、公会柜台、护照桌面和轻量动画。
- 工作层：标准 DOM 表单、列表、对话框、交易状态和错误提示。
- 不把上传、钱包确认、哈希校验和 HR 验证结果放进 Canvas。
- 第一屏直接进入可操作的冒险公告板，不开发营销式落地页。
- 游戏操作不要求方向键移动；页面导航、按钮和表单是主要操作方式。

## 2. 视觉方向

### 2.1 风格定位

采用“16-bit 职业冒险公会 + 现代链上工作台”：

- 场景使用低分辨率像素资产、硬边阴影和逐帧角色动画。
- 信息面板保持紧凑、规则和清晰，避免所有内容都做成厚重游戏对话框。
- 不使用满屏紫色渐变。Monad 紫只作为链上状态和网络识别色。
- 页面主色同时包含炭黑、纸白、苔绿、警示红、金黄和 Monad 紫。

### 2.2 颜色 Token

```css
:root {
  --ink: #18181b;
  --paper: #f4f1e8;
  --surface: #fffdf7;
  --line: #34343a;
  --monad: #836ef9;
  --monad-dark: #5e4bd8;
  --quest: #d8a62a;
  --success: #2f8f59;
  --danger: #c7473d;
  --muted: #6f706f;
  --sky: #9bc7d6;
}
```

状态不能只依赖颜色，必须同时使用图标和文字。

### 2.3 字体

- 像素标题：使用支持中英文的像素字体资源；若中文字形质量不足，则标题改用清晰黑体并保留像素描边容器。
- 正文、表单和技术信息：`Inter` + `Noto Sans SC`。
- 地址、哈希和交易 ID：`JetBrains Mono`。
- 像素字体只用于场景标题、任务等级和少量标签，禁止用于长正文。

### 2.4 图标与素材

- 通用操作图标使用 Lucide：钱包、复制、外链、上传、刷新、撤销、二维码。
- 游戏语义资产使用独立像素 PNG/WebP：设计师角色、公会 NPC、卷轴、印章、护照、传送门。
- 像素图按整数倍缩放并使用 `image-rendering: pixelated`。
- 首版只需 1 套角色基础造型、4 个职业配件、4 个场景背景和 8-12 个状态物件。

## 3. 全局页面框架

### 3.1 桌面布局

```text
+------------------------------------------------------------------+
| Proof of Quest | 公告板  当前任务  护照     Monad 10143  [钱包] |
+------------------------------------------------------------------+
| 场景标题 / 地点状态 / 当前任务进度                               |
+------------------------------+-----------------------------------+
|                              |                                   |
| 像素场景与角色反馈           | 主要业务工作区                    |
| 约 40%                       | 约 60%                            |
|                              | 表单 / 列表 / 验证结果            |
|                              |                                   |
+------------------------------+-----------------------------------+
| 链上状态栏：RPC / 合约 / 最近同步 / 交易状态                     |
+------------------------------------------------------------------+
```

- 页面主体最大宽度建议 `1440px`。
- 工作区最小宽度 `560px`，避免表单内容被像素场景挤压。
- 场景高度稳定，切换任务状态时不能引发页面跳动。
- 公共 HR 验证页不显示复杂导航，只保留品牌、网络和凭证状态。

### 3.2 移动布局
 
```text
+--------------------------+
| 顶栏 + 钱包              |
+--------------------------+
| 低高度像素场景 16:7      |
+--------------------------+
| 状态分段控件             |
+--------------------------+
| 业务内容                 |
| 单列表单 / 凭证信息      |
+--------------------------+
| 底部导航                 |
+--------------------------+
```

- 场景降为背景反馈，不占用首屏大部分高度。
- 主操作使用底部固定操作栏，但不得遮挡表单错误和系统提示。
- 钱包地址、哈希和交易 ID 中间截断，并提供复制按钮。
- 桌面 hover 信息在移动端必须可点击打开。

## 4. 信息架构与路由

| 路由 | 页面 | 角色 | 核心任务 |
| --- | --- | --- | --- |
| `/` | 冒险公告板 | 全部 | 浏览、创建或进入匿名任务 |
| `/quests/[id]` | 任务场景 | 签发方/设计师 | 接受任务、提交成果、查看进度 |
| `/guild/quests/[id]/review` | 公会验收室 | 签发方 | 审核、签发和撤销凭证 |
| `/passport/[address]` | 冒险者护照 | 设计师/访客 | 展示职业贡献与分享 |
| `/verify/[credentialId]` | 护照验证态 | HR/访客 | 无钱包验证 Monad 凭证 |

`/verify` 复用护照的凭证视觉组件，是护照的公开验证状态，不单独创造第五套场景。

## 5. 页面一：冒险公告板

### 5.1 页面目标

让用户进入产品后立即理解当前有什么任务、自己是什么角色、下一步可以做什么。

### 5.2 页面布局

```text
+------------------------------------------------------------------+
| 冒险公告板                         [我发布的] [邀请我的] [新任务] |
+------------------------+-----------------------------------------+
| 像素公会大厅           | 筛选：全部 / 待接受 / 进行中 / 已完成   |
|                        +-----------------------------------------+
| NPC 发布任务           | [任务卷轴] 电商视觉 · 执行设计         |
| 角色在公告板前待机     | 匿名行业 · 7/20 截止 · INVITED         |
| Monad 传送门微光       |                         [查看任务]      |
|                        +-----------------------------------------+
|                        | [任务卷轴] UI 界面 · 主设计             |
+------------------------+-----------------------------------------+
```

### 5.3 关键组件

- `WorldHeader`：品牌、主要导航、Monad 网络状态、钱包菜单。
- `GuildHallScene`：公会大厅、公告板、设计师角色和 NPC。
- `QuestFilters`：角色与状态分段控件。
- `QuestRow`：紧凑任务行，不使用大面积重复卡片。
- `CreateQuestDrawer`：右侧抽屉创建任务，不跳转到营销式新页面。
- `WalletGate`：未连接钱包时，只在执行创建/接受操作时触发连接。

### 5.4 创建任务流程

1. 选择项目类别和设计角色。
2. 选择开始/预计完成时间。
3. 选择保密等级；等级 2 自动禁用公开摘要。
4. 填写去标识化摘要模板。
5. 输入设计师钱包或生成一次性邀请链接。
6. 确认链下任务信息，不发起链上交易。

表单始终显示“客户名、价格、联系方式和未发布信息不得填写”的短提示。命中疑似敏感内容时显示二次确认，但不宣称自动识别绝对可靠。

### 5.5 游戏反馈

- 新任务创建成功：NPC 把新卷轴钉到公告板，持续 600-800ms。
- 收到邀请：卷轴边缘有缓慢金色像素闪烁。
- 任务完成：卷轴盖上绿色公会印章。
- 已撤销：印章变红并显示“凭证已失效”，卷轴仍保留。

## 6. 页面二：任务场景

### 6.1 页面目标

围绕一个任务完成接受、提交、驳回后修改和查看链上结果，不让用户在多个页面之间来回寻找状态。

### 6.2 页面布局

```text
+------------------------------------------------------------------+
| 电商视觉设计 / 详情页执行设计师             状态：SUBMITTED      |
+------------------------------------------------------------------+
| [邀请]---[接受]---[提交]---[验收]---[Monad 铭刻]                 |
+------------------------+-----------------------------------------+
| 像素工作室             | 公开贡献摘要                            |
| 角色在绘图桌前         | [textarea............................]  |
| 当前状态决定动作       |                                         |
|                        | 成果数字指纹                            |
|                        | [上传区] 文件名 / 大小 / SHA-256        |
|                        |                                         |
|                        | [保存草稿] [提交公会验收]               |
+------------------------+-----------------------------------------+
```

### 6.3 状态驱动界面

| 状态 | 场景反馈 | 工作区主操作 |
| --- | --- | --- |
| `INVITED` | 角色收到任务卷轴 | 接受 / 拒绝 |
| `ACCEPTED` | 角色坐到绘图桌 | 上传成果并填写摘要 |
| `SUBMITTED` | 成果箱被封印 | 等待公会；允许查看版本 |
| `REJECTED` | NPC 返回修改便笺 | 查看原因并重新提交 |
| `APPROVED` | 公会印章准备完成 | 等待签发方铭刻 |
| `ISSUING` | Monad 传送门流动 | 显示钱包/receipt 状态，禁止重复提交 |
| `ISSUED` | 角色获得履历徽记 | 查看护照和交易 |
| `REVOKED` | 徽记变为失效封印 | 查看撤销时间和历史 |

### 6.4 文件上传体验

- 支持拖放和文件选择两种方式。
- 上传前在浏览器计算 SHA-256，显示确定进度而非无限 loading。
- 明确分开“本地计算指纹”和“上传私有证据”两个状态。
- 上传成功后显示服务端复算结果；不一致时阻止提交。
- 显示版本号、文件名、大小、时间和哈希复制按钮。
- 哈希默认折叠显示，展开后使用等宽字体完整展示。
- 不在公开页面生成缩略图，也不暴露对象存储 URL。

## 7. 页面三：公会验收室

### 7.1 页面目标

让签发方清楚知道自己验收了什么、将永久公开什么，以及当前 Monad 交易是否真正成功。

### 7.2 页面布局

```text
+------------------------------------------------------------------+
| 公会验收室 / Quest #PQ-014                  [返回任务]            |
+------------------------+-----------------------------------------+
| 柜台与鉴定 NPC         | 提交版本 V2                             |
| 桌面放置成果箱         | 文件指纹 / 公开摘要 / 任务时间          |
|                        +-----------------------------------------+
|                        | 永久公开到 Monad 的字段预览              |
|                        | issuer / recipient / category / hashes  |
|                        +-----------------------------------------+
|                        | [驳回修改] [确认贡献并铭刻到 Monad]      |
+------------------------+-----------------------------------------+
```

### 7.3 验收流程

1. 查看最终提交版本和证据哈希。
2. 选择驳回或确认贡献；驳回必须填写原因。
3. 确认贡献后进入只读的上链字段预览。
4. 展示 Monad Testnet、chain ID、合约、recipient 和预计 gas。
5. 勾选“我确认该设计师完成了上述贡献”。
6. 点击“铭刻到 Monad”，触发钱包交易。
7. 分阶段显示：等待钱包 -> 已广播 -> Monad 执行中 -> receipt 成功。
8. 只有 receipt 成功并解码到正确事件后才播放获得徽记动画。

### 7.4 交易状态组件

`TransactionStepper` 必须覆盖：

- 等待用户签名。
- 用户取消。
- 网络不正确，并提供切换 Monad Testnet 操作。
- 模拟失败和可读的合约错误。
- 交易已广播但待确认。
- receipt revert。
- receipt 成功，显示 credentialId、交易哈希、复制和浏览器入口。

页面刷新后从数据库索引与 Monad receipt 恢复状态，不能退回到空白步骤。

### 7.5 撤销交互

- 撤销使用独立危险操作对话框，不与普通操作并列。
- 显示“撤销不会删除历史内容”。
- 填写公开原因后生成原因摘要预览。
- 成功后将徽记切换为红色失效封印，不删除原始凭证内容。

## 8. 页面四：冒险者护照与 HR 验证

### 8.1 设计师护照 `/passport/[address]`

```text
+------------------------------------------------------------------+
| 冒险者护照                0x12ab...89ef      [分享] [二维码]      |
+------------------------+-----------------------------------------+
| 像素角色立绘           | 职业履历  4                              |
| 装备随履历轻量变化     | [有效 3] [已撤销 1]                     |
|                        +-----------------------------------------+
| 设计师 Lv.4            | 2026.07  电商视觉 · 执行设计            |
| 已验证贡献 3           | 公会 0x... · Monad 已验证       [详情]  |
|                        +-----------------------------------------+
|                        | 2026.06  UI 界面 · 主设计                |
+------------------------+-----------------------------------------+
```

- 等级只代表有效贡献数量或里程碑，不代表能力评分。
- 职业配件由类别映射，例如 UI 网格尺、插画笔、排版卷轴；不生成可交易装备。
- 凭证按时间线展示，默认有效在前，撤销记录仍保留。
- 隐藏按钮只控制平台列表可见性，并提示链上仍可查询。

### 8.2 HR 公开验证 `/verify/[credentialId]`

HR 页面弱化游戏操作，保留护照和印章视觉，但以可信度判断为第一优先级。

```text
+------------------------------------------------------------------+
| Proof of Quest                         Monad Testnet · 实时读取    |
+------------------------------------------------------------------+
| [绿色印章] 凭证有效                                          |
| 该结果证明 0xIssuer 在 Monad 上向 0xDesigner 作出了以下声明。   |
+------------------------------------------------------------------+
| 项目类别 | 电商视觉设计          角色 | 详情页执行设计师          |
| 时间     | 2026-07-03 - 07-20    证据 | 文件指纹 + 公会确认      |
| 摘要     | 完成 6 个商品详情页的视觉排版与两轮修改              |
+------------------------------------------------------------------+
| 签发方身份标签（链下） | 文件指纹 | 完整性校验                  |
| [展开链上技术信息] [在 MonadVision 查看]                         |
+------------------------------------------------------------------+
| 说明：链上验证声明来源和状态，不自动证明设计质量或版权归属。    |
+------------------------------------------------------------------+
```

### 8.3 四种验证结果

| 结果 | 表现 | 主操作 |
| --- | --- | --- |
| 有效 | 绿色印章 + “凭证有效” | 查看 Monad 交易、复制字段 |
| 已撤销 | 红色破损印章 + 撤销时间 | 查看历史和撤销原因 |
| 未找到 | 空白护照页 + “未找到该凭证” | 检查 ID |
| 网络错误 | 灰色待验证印章 | 重试 RPC；不得显示有效 |

链下 `metadataDigest` 校验失败时使用橙红警告，整体结论不得保持绿色。

## 10. 动效与声音

### 10.1 动效规则

- 待机角色：4-6 帧，800-1200ms 循环。
- 新任务钉上公告板：600-800ms，仅播放一次。
- 哈希计算：像素扫描线跟随真实进度，不用虚假循环。
- Monad 签发：传送门动画可以循环，但交易步骤文字必须独立可读。
- 签发成功：印章落下 + 徽记出现，总时长不超过 1000ms。
- 撤销：不做爆炸或销毁动画，使用印章破损表达“历史仍存在但已失效”。
- 遵循 `prefers-reduced-motion`，关闭循环位移和闪烁。

### 10.2 声音

MVP 默认静音。可增加右上角声音开关，只提供卷轴、印章和成功三个轻量音效；钱包错误与危险操作不能只靠声音表达。

## 11. 前端状态与数据策略

### 11.1 状态划分

- Server state：项目、提交、身份标签、链下索引，使用 TanStack Query。
- Wallet state：账户、chain、连接器，使用 wagmi。
- Chain state：凭证、receipt、事件，通过 viem 读取并写入 Query cache。
- Form state：React Hook Form + Zod。
- UI state：抽屉、对话框、当前场景动画，保持组件本地状态。

不要创建一个包含所有业务数据的全局 store。

### 11.2 权威来源

- 任务状态由 API 返回。
- 钱包账户和当前网络由钱包提供方返回。
- 凭证有效/撤销状态由 Monad 合约返回。
- 数据库中的链上记录只用于索引和加速。
- RPC 读取失败时保留最近结果仅作灰色缓存展示，并明确“当前无法实时核验”。

### 11.3 数据刷新

- 交易等待阶段轮询 receipt，并支持页面恢复。
- 护照加载时先取索引，再批量读取合约当前状态。
- HR 验证页每次打开必须触发实时读取；显示最近核验时间。
- 事件同步延迟时，可通过 credentialId 直接读取合约，不等待索引器。

## 12. 可访问性与易用性

- 所有核心操作都能使用键盘完成。
- 像素图设置空 alt 或准确 alt，不朗读纯装饰场景。
- Canvas 若用于背景，必须提供 DOM 等价内容。
- 状态同时使用图标、颜色和文字。
- 对话框正确管理焦点，关闭后返回触发按钮。
- 表单错误放在字段附近，并在提交失败时聚焦第一个错误。
- 触控目标至少 `44x44px`。
- 正文对比度达到 WCAG AA。
- 地址和哈希可复制，复制按钮提供成功反馈。
- HR 页面不要求理解“attestation”“soulbound”等术语。

## 13. 响应式断点与稳定尺寸

```text
mobile:  320-767px
tablet:  768-1023px
desktop: 1024-1439px
wide:    >= 1440px
```

- 场景容器使用固定 `aspect-ratio`，避免素材加载导致布局移动。
- 桌面双栏使用 `minmax(320px, 0.75fr) minmax(560px, 1.25fr)`。
- 任务进度条各节点固定宽度，长标签允许两行但不改变节点尺寸。
- 凭证印章、二维码和像素角色使用稳定尺寸。
- 320px 宽度下最长地址、类别和角色名称不能溢出。

## 14. 前端开发顺序

### Phase 1：设计系统与应用骨架

- 建立颜色、间距、字体、边框、阴影和状态 Token。
- 完成 `WorldHeader`、页面框架、网络/钱包状态。
- 完成四个场景的静态低保真布局。
- 建立 Storybook 或组件演示路由，覆盖空、加载、错误、有效和撤销状态。

### Phase 2：Monad 纵向切片

- 连接 Monad Testnet。
- 完成 `OnchainPreview` 和 `TransactionStepper`。
- 打通签发 -> receipt -> `/verify/[credentialId]`。
- 完成错误网络、拒签、revert、RPC 故障和未找到状态。

### Phase 3：任务闭环

- 公告板列表和创建抽屉。
- 任务状态进度和角色权限。
- 文件上传、SHA-256、版本与提交。
- 公会审批、驳回、签发和撤销。

### Phase 4：像素体验

- 替换临时场景为最终像素资产。
- 绑定角色动作与真实业务状态。
- 完成护照角色、贡献徽记和二维码。
- 加入 reduced-motion、移动端场景裁切和资源懒加载。

### Phase 5：视觉与 E2E 验收

- Playwright 覆盖桌面 `1440x900`、平板 `768x1024`、手机 `390x844` 和 `320x568`。
- 截图检查文字溢出、场景裁切、弹窗遮挡和底栏覆盖。
- 检查所有交易阶段的按钮防重复提交。
- 使用无钱包浏览器验证公开页面。
- 低速网络下检查像素资源未加载时仍可完成业务操作。

## 15. 前端验收标准

1. 首屏是可操作的冒险公告板，用户不需要经过营销介绍页。
2. 四个核心页面拥有统一世界观，但关键工作区保持清晰、高密度和可扫描。
3. 游戏动画与真实状态一致，不提前播放“签发成功”。
4. 用户能区分钱包签名、交易广播、receipt 成功和链上撤销。
5. HR 无钱包也能理解谁签发、给谁、证明什么、当前是否有效。
6. 所有核心功能在 320px 手机和桌面端均无文字溢出或内容遮挡。
7. 关闭动画、关闭声音或像素资源加载失败时，完整业务流程仍可使用。
8. 有效、撤销、未找到、RPC 错误和完整性失败均有独立页面状态。
9. 客户信息、文件 URL 和私有证据从不出现在公开 DOM、分享卡片或页面元数据中。
10. 所有 Monad 浏览器链接、chain ID、合约地址和交易哈希与实际网络一致。
